Chapter 4

Database

Learn how LinkSpice saves your data on your phone so it never disappears.

What You'll Learn

In this chapter, you'll understand:

  • What a database is — a spreadsheet that lives on your phone
  • SQLite — the type of database LinkSpice uses
  • Schema — the blueprint that defines how data is organized
  • CRUD — the four operations: Create, Read, Update, Delete
  • How LinkSpice connects it all — from schema to code to data on screen

What is a Database?

A database is like a spreadsheet that lives on your phone. Instead of opening Excel or Google Sheets, the data sits right inside the app, ready to use instantly.

Think of it like this: imagine you have a notebook where you write down every link you want to save. Each page has the URL, a title, and maybe a description. When you close the notebook, your links are still there when you open it again. That's exactly what a database does — it stores information permanently so it survives app restarts.

Rows and Columns

A database stores data in tables. A table is like a spreadsheet page. It has:

  • Columns — the categories of data (like "URL", "Title", "Description")
  • Rows — each individual entry (one saved link is one row)

Here's what LinkSpice's links table looks like:

links table — a spreadsheet-like view 
| id           | url                    | title          | domain        | is_pinned |
|--------------|------------------------|----------------|---------------|-----------|
| abc123       | https://react.dev      | React Docs     | react.dev     | 1         |
| def456       | https://expo.dev       | Expo Docs      | expo.dev      | 0         |
| ghi789       | https://github.com     | GitHub         | github.com    | 0         |

Each row is one link. Each column holds a piece of information about that link. The id column is special — it's a unique identifier so we can find any specific link later.

⚡ Why this matters

Without a database, your links would disappear every time you close the app. Variables in code are temporary — they're gone when the app stops. A database writes data to the phone's storage, so it persists across sessions.

SQLite — The Database LinkSpice Uses

LinkSpice uses SQLite, a lightweight database that runs right on the phone. No server needed, no internet required. The entire database lives in a single file on the device.

Why SQLite?

  • No server — it runs inside the app itself
  • Fast — reading and writing data is nearly instant
  • Reliable — used by millions of apps (including every phone's contacts app)
  • Offline-first — works without internet

In Expo, SQLite is available through the expo-sqlite package. It gives us simple functions to run SQL queries against the database.

The Schema — Your Data Blueprint

Before you can store anything, you need to define what you're storing. That's what a schema does. It's the blueprint that tells the database: "Here are the tables, here are the columns, here's how they relate to each other."

LinkSpice has two tables: spaces and links. A space is a folder that holds links. Here's the actual schema:

src/db/schema.ts 
import type { DbClient } from './client';

const SCHEMA_SQL = `
CREATE TABLE IF NOT EXISTS spaces (
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL,
  icon TEXT NOT NULL DEFAULT 'folder',
  color TEXT NOT NULL DEFAULT '#7C5CFF',
  position INTEGER NOT NULL DEFAULT 0,
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL
);

CREATE TABLE IF NOT EXISTS links (
  id TEXT PRIMARY KEY,
  space_id TEXT,
  url TEXT NOT NULL UNIQUE,
  title TEXT NOT NULL,
  description TEXT,
  domain TEXT NOT NULL,
  favicon TEXT,
  thumbnail TEXT,
  tags TEXT NOT NULL DEFAULT '[]',
  is_pinned INTEGER NOT NULL DEFAULT 0,
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL,
  FOREIGN KEY (space_id) REFERENCES spaces(id) ON DELETE SET NULL
);

CREATE INDEX IF NOT EXISTS idx_links_space_id ON links(space_id);
CREATE INDEX IF NOT EXISTS idx_links_created_at ON links(created_at);
CREATE INDEX IF NOT EXISTS idx_links_is_pinned ON links(is_pinned);
`;

export const SCHEMA_VERSION = 2;

export function migrate(db: DbClient): void {
  db.exec('PRAGMA foreign_keys = ON;');
  const row = db.get<{ user_version: number }>('PRAGMA user_version');
  const currentVersion = row?.user_version ?? 0;

  if (currentVersion >= SCHEMA_VERSION) {
    return;
  }

  if (currentVersion === 0) {
    db.exec(SCHEMA_SQL);
  }

  db.exec(`PRAGMA user_version = ${SCHEMA_VERSION}`);
}

Let's break this down piece by piece:

The spaces table

  • id TEXT PRIMARY KEY — a unique text identifier (like "abc123")
  • name TEXT NOT NULL — the space name (like "Work" or "Personal"), required
  • icon TEXT NOT NULL DEFAULT 'folder' — an icon name, defaults to "folder"
  • color TEXT NOT NULL DEFAULT '#7C5CFF' — a hex color, defaults to purple
  • position INTEGER NOT NULL DEFAULT 0 — ordering position
  • created_at INTEGER NOT NULL — timestamp when created
  • updated_at INTEGER NOT NULL — timestamp when last modified

The links table

  • id TEXT PRIMARY KEY — unique identifier
  • space_id TEXT — which space this link belongs to (can be null for "loose" links)
  • url TEXT NOT NULL UNIQUE — the link URL, must be unique
  • title TEXT NOT NULL — the display title
  • description TEXT — optional description
  • domain TEXT NOT NULL — extracted domain like "github.com"
  • favicon TEXT — optional favicon URL
  • thumbnail TEXT — optional thumbnail image
  • tags TEXT NOT NULL DEFAULT '[]' — a JSON array of tags stored as text
  • is_pinned INTEGER NOT NULL DEFAULT 0 — 0 = not pinned, 1 = pinned
  • created_at INTEGER NOT NULL — timestamp
  • updated_at INTEGER NOT NULL — timestamp

The foreign key

The line FOREIGN KEY (space_id) REFERENCES spaces(id) ON DELETE SET NULL creates a relationship: each link belongs to a space. If that space is deleted, the link isn't deleted — its space_id just becomes null (it becomes a "loose" link).

Indexes

The three CREATE INDEX lines at the bottom create shortcuts for the database. Instead of scanning every row to find links by space or date, the index lets the database jump straight to what it needs. It's like the index at the back of a textbook.

Migration

The migrate() function handles schema upgrades. It checks the current version number and applies any new changes. This ensures the database structure stays up to date as the app evolves.

Database Connection

Before you can run queries, you need to connect to the database. LinkSpice splits this into three files that work together.

The Client Interface

This defines what every database client must be able to do:

src/db/client.ts 
export type BindValue = string | number | boolean | null;

export interface DbRunResult {
  changes: number;
  lastInsertRowid: number;
}

export interface DbClient {
  exec(sql: string): void;
  run(sql: string, params?: BindValue[]): DbRunResult;
  all<T = Record<string, unknown>>(sql: string, params?: BindValue[]): T[];
  get<T = Record<string, unknown>>(sql: string, params?: BindValue[]): T | null;
}

Four methods:

  • exec — run raw SQL (no results returned)
  • run — execute an INSERT, UPDATE, or DELETE and get back how many rows changed
  • all — fetch multiple rows (like getting all links in a space)
  • get — fetch a single row (like finding one link by ID)

The Expo Client

This wraps Expo's SQLite library to match the client interface:

src/db/expo-client.ts 
import type { SQLiteDatabase } from 'expo-sqlite';
import type { BindValue, DbClient, DbRunResult } from './client';

export function createExpoClient(db: SQLiteDatabase): DbClient {
  return {
    exec: (sql: string): void => {
      db.execSync(sql);
    },
    run: (sql: string, params: BindValue[] = []): DbRunResult => {
      const result = db.runSync(sql, params);
      return {
        changes: result.changes,
        lastInsertRowid: Number(result.lastInsertRowId),
      };
    },
    all: <T>(sql: string, params: BindValue[] = []): T[] =>
      db.getAllSync<T>(sql, params),
    get: <T>(sql: string, params: BindValue[] = []): T | null =>
      db.getFirstSync<T>(sql, params),
  };
}

It translates our simple DbClient methods into Expo's runSync, getAllSync, and getFirstSync calls. This abstraction means if we ever switch to a different SQLite library, we only change this one file.

Getting the Database

The db.ts file ties it all together — it opens the database file and runs the migration:

src/db/db.ts 
import { openDatabaseSync } from 'expo-sqlite';
import type { DbClient } from './client';
import { createExpoClient } from './expo-client';
import { migrate } from './schema';

let client: DbClient | null = null;

export function getDbClient(): DbClient {
  if (!client) {
    const db = openDatabaseSync('linkspace.db');
    client = createExpoClient(db);
    migrate(client);
  }
  return client;
}

The getDbClient() function does three things:

  1. Opens (or creates) a file called linkspace.db on the phone
  2. Wraps it with our Expo client
  3. Runs the migration to make sure the tables exist

It also caches the client in a variable so the database is only opened once. Every time you call getDbClient(), you get the same connection back.

Row Mapping — Database to JavaScript

SQLite returns data as plain objects with snake_case column names (like space_id, created_at). But our TypeScript code uses camelCase (like spaceId, createdAt). The rows.ts file handles this translation.

src/db/rows.ts 
import type { Link, Space } from '../types';

interface LinkRow {
  id: string;
  space_id: string | null;
  url: string;
  title: string;
  description: string | null;
  domain: string;
  favicon: string | null;
  thumbnail: string | null;
  tags: string;
  is_pinned: number;
  created_at: number;
  updated_at: number;
}

export function mapLinkRow(row: LinkRow): Link {
  return {
    id: row.id,
    spaceId: row.space_id,
    url: row.url,
    title: row.title,
    description: row.description,
    domain: row.domain,
    favicon: row.favicon,
    thumbnail: row.thumbnail,
    tags: parseTags(row.tags),
    isPinned: row.is_pinned === 1,
    createdAt: row.created_at,
    updatedAt: row.updated_at,
  };
}

export function parseTags(raw: string): string[] {
  try {
    const parsed: unknown = JSON.parse(raw);
    if (Array.isArray(parsed)) {
      return parsed.filter((t): t is string => typeof t === 'string');
    }
  } catch {
    // Malformed tag data is treated as no tags.
  }
  return [];
}

export function serializeTags(tags: string[]): string {
  return JSON.stringify([...new Set(tags.map((t) => t.trim()).filter(Boolean))]);
}

Three key functions:

  • mapLinkRow — converts a database row into a Link object that the rest of the app understands. It renames fields (space_id → spaceId), converts the is_pinned integer (0/1) to a boolean (true/false), and parses the JSON tags string.
  • parseTags — safely converts the JSON string '["react","expo"]' into a JavaScript array ["react", "expo"]. If the data is corrupted, it returns an empty array instead of crashing.
  • serializeTags — does the reverse: converts an array of tags into a JSON string for storage. It also removes duplicates and trims whitespace.
✔ Tip

Notice how SQLite stores booleans as integers (0 or 1) and tags as a JSON string. Databases have their own type system, and row mapping bridges the gap between what the database stores and what your code expects.

CRUD Operations

CRUD stands for the four things you can do with data: Create, Read, Update, and Delete. Every database operation falls into one of these categories. Let's look at how LinkSpice implements each one.

Create — Adding a new link

src/repositories/links.ts — createLink 
export function createLink(db: DbClient, input: CreateLinkInput): Link {
  const now = Date.now();
  const url = input.url.trim();
  const link: Link = {
    id: newId(),
    spaceId: input.spaceId ?? null,
    url,
    title: displayTitle(url, input.title ?? null),
    description: input.description ?? null,
    domain: input.domain ?? getDomain(url),
    favicon: input.favicon ?? null,
    thumbnail: input.thumbnail ?? null,
    tags: input.tags ?? [],
    isPinned: input.isPinned ?? false,
    createdAt: input.createdAt ?? now,
    updatedAt: now,
  };

  db.run(
    `INSERT INTO links
       (id, space_id, url, title, description, domain, favicon, thumbnail, tags, is_pinned, created_at, updated_at)
     VALUES (?, ?, ?, ?, ?, ?, ?, ?, ?, ?, ?, ?)`,
    [
      link.id,
      link.spaceId,
      link.url,
      link.title,
      link.description,
      link.domain,
      link.favicon,
      link.thumbnail,
      serializeTags(link.tags),
      link.isPinned ? 1 : 0,
      link.createdAt,
      link.updatedAt,
    ]
  );
  return link;
}

This function:

  1. Creates a Link object with all the fields filled in (generating an ID, extracting the domain, etc.)
  2. Runs an INSERT INTO SQL statement with ? placeholders for each value
  3. Returns the created link so the rest of the app can use it

The ? placeholders are called parameters. They prevent SQL injection attacks — a security risk where malicious input could damage your database. Never put user input directly into SQL strings.

Read — Fetching links

src/repositories/links.ts — listBySpace 
export function listBySpace(db: DbClient, spaceId: string | null): Link[] {
  const rows = db.all(
    `SELECT ${CURRENTLY_SELECTED_COLUMNS} FROM links
     WHERE space_id IS ? ORDER BY created_at DESC`,
    spaceId === null ? [null] : [spaceId]
  );
  return rows.map((row) => mapLinkRow(row as never));
}

This fetches all links in a space. It uses SELECT to get rows, WHERE to filter by space, and ORDER BY created_at DESC to show newest first. The raw rows are then mapped to Link objects.

src/repositories/links.ts — getLink 
function selectLink(db: DbClient, id: string): Link | null {
  const row = db.get(
    `SELECT ${CURRENTLY_SELECTED_COLUMNS} FROM links WHERE id = ?`,
    [id]
  );
  return row ? mapLinkRow(row as never) : null;
}

export function getLink(db: DbClient, id: string): Link | null {
  return selectLink(db, id);
}

This fetches a single link by its ID. It uses db.get (which returns one row or null) instead of db.all (which returns an array).

Update — Editing a link

src/repositories/links.ts — updateLink 
export function updateLink(
  db: DbClient,
  id: string,
  patch: UpdateLinkInput
): Link | null {
  const existing = selectLink(db, id);
  if (!existing) {
    return null;
  }

  const next: Link = {
    ...existing,
    title: patch.title !== undefined ? patch.title.trim() || existing.title : existing.title,
    spaceId: patch.spaceId !== undefined ? patch.spaceId : existing.spaceId,
    description:
      patch.description !== undefined ? patch.description : existing.description,
    thumbnail: patch.thumbnail !== undefined ? patch.thumbnail : existing.thumbnail,
    tags: patch.tags !== undefined ? patch.tags : existing.tags,
    updatedAt: Date.now(),
  };

  db.run(
    `UPDATE links
       SET title = ?, space_id = ?, description = ?, thumbnail = ?, tags = ?, updated_at = ?
     WHERE id = ?`,
    [
      next.title,
      next.spaceId,
      next.description,
      next.thumbnail,
      serializeTags(next.tags),
      next.updatedAt,
      id,
    ]
  );
  return next;
}

This function:

  1. Fetches the existing link first
  2. Applies only the fields that changed (the "patch")
  3. Runs an UPDATE SQL statement
  4. Returns the updated link

The ...existing syntax is called the spread operator. It copies all fields from the existing link, then the patch overwrites only the fields that were provided.

Delete — Removing a link

src/repositories/links.ts — deleteLink 
export function deleteLink(db: DbClient, id: string): void {
  db.run('DELETE FROM links WHERE id = ?', [id]);
}

The simplest operation — just DELETE FROM with a WHERE clause to target the specific link. One line of SQL does the job.

⚡ Why this matters

Every database operation in LinkSpice follows this pattern: receive input, run SQL, return results. The repository layer keeps all database logic in one place, so the rest of the app never has to think about SQL.

Building It — Step by Step

Let's walk through how you'd create a simple database, add some data, and read it back. This mirrors what LinkSpice does behind the scenes.

1

Create the database file

When the app first opens, getDbClient() runs. It creates a file called linkspace.db on the phone and opens a connection to it.

2

Create the tables

The migrate() function runs the schema SQL. This creates the spaces and links tables if they don't exist yet. The IF NOT EXISTS keyword means it won't throw an error if the tables already exist.

3

Add some data

You could run SQL directly to insert a link:

Direct SQL (what LinkSpice does internally) 
db.run(
  `INSERT INTO links (id, url, title, domain, is_pinned, created_at, updated_at)
   VALUES (?, ?, ?, ?, ?, ?, ?)`,
  ['abc123', 'https://react.dev', 'React Docs', 'react.dev', 0, 1690000000000, 1690000000000]
);
4

Read it back

To fetch that link and display it on screen:

Fetching a link 
const link = db.get('SELECT * FROM links WHERE id = ?', ['abc123']);
// Returns: { id: 'abc123', url: 'https://react.dev', title: 'React Docs', ... }
5

Update it

If you pin that link:

Updating a link 
db.run('UPDATE links SET is_pinned = 1, updated_at = ? WHERE id = ?',
  [Date.now(), 'abc123']);
6

Delete it

And if you remove it:

Deleting a link 
db.run('DELETE FROM links WHERE id = ?', ['abc123']);
