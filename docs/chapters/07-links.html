What is a Link?

A link is the fundamental unit of data in Link Space. Every time you save a URL, the app creates a Link object — a record in the database that holds the URL, a title, a description, which space it belongs to, tags, and whether it's pinned.

Here is the Link type from the app's type definitions:

src/types.ts 
export interface Link {
  id: string;
  spaceId: string | null;
  url: string;
  title: string;
  description: string | null;
  domain: string;
  favicon: string | null;
  thumbnail: string | null;
  tags: string[];
  isPinned: boolean;
  createdAt: number;
  updatedAt: number;
}

Each field has a purpose:

  • id — a unique identifier generated when the link is created
  • spaceId — which space this link belongs to (null means it's unorganized)
  • url — the normalized URL the user saved
  • title — the page title, either extracted from the website or written by the user
  • domain — the website name (like github.com)
  • favicon and thumbnail — small image and preview image from the site
  • tags — labels the user adds for organization
  • isPinned — whether this link is marked as important
Why links are the core

Everything in Link Space revolves around links. Spaces group them, tags label them, pins highlight them. Understanding the Link type is the key to understanding the entire app.

Let's break down the key parts:

  • expanded — controls whether the panel is visible. When false, the panel shows a floating "Add Link" button (the FAB). When true, the panel slides up from the bottom.
  • onUrlChange — called every time the user types or pastes a URL. It validates the URL and triggers metadata fetching.
  • fetchMetadata — goes to the URL, downloads the HTML, and extracts the title, description, favicon, and thumbnail using Open Graph meta tags.
  • findDup — checks if this URL has already been saved. If so, it shows a "duplicate" warning.
  • onSave — the final step: normalizes the URL, fetches metadata if needed, and calls saveLink to write to the database.
The slide-up pattern

The panel uses Animated.Value for a smooth slide-up animation. The user can also swipe down to dismiss it using PanResponder. This is a common pattern for mobile modals — a full-screen sheet that slides from the bottom.

Saving a Link — The Full Flow

When a user saves a link, here's what happens step by step:

1

User pastes a URL

The user types or pastes a URL into the input field. onUrlChange is called, which validates the URL format with isValidUrl().

2

URL is validated and checked for duplicates

normalizeUrl() cleans up the URL (adds https:// if missing, strips trailing slashes). Then findDup() checks the database — if this URL already exists, the user sees a "duplicate" warning.

3

Metadata is fetched from the web

fetchMetadata() fetches the page HTML and extracts the title, description, favicon, and thumbnail image using Open Graph meta tags (og:title, og:image). This happens asynchronously, so a loading skeleton shows while waiting.

4

User picks a space and optional details

The user selects which space to save the link into, and optionally adds a custom title, tags, and notes.

5

Link is saved to the database

saveLink() calls createLink() in the repository, which inserts a new row into the links table. Then notifyDbChanged() triggers all subscribed hooks to re-render.

Here's the repository function that actually writes to the database:

src/repositories/links.ts 
export function createLink(db: DbClient, input: CreateLinkInput): Link {
  const now = Date.now();
  const url = input.url.trim();
  const link: Link = {
    id: newId(),
    spaceId: input.spaceId ?? null,
    url,
    title: displayTitle(url, input.title ?? null),
    description: input.description ?? null,
    domain: input.domain ?? getDomain(url),
    favicon: input.favicon ?? null,
    thumbnail: input.thumbnail ?? null,
    tags: input.tags ?? [],
    isPinned: input.isPinned ?? false,
    createdAt: input.createdAt ?? now,
    updatedAt: now,
  };

  db.run(
    `INSERT INTO links
       (id, space_id, url, title, description, domain, favicon, thumbnail, tags, is_pinned, created_at, updated_at)
     VALUES (?, ?, ?, ?, ?, ?, ?, ?, ?, ?, ?, ?)`,
    [
      link.id, link.spaceId, link.url, link.title,
      link.description, link.domain, link.favicon, link.thumbnail,
      serializeTags(link.tags), link.isPinned ? 1 : 0,
      link.createdAt, link.updatedAt,
    ]
  );
  return link;
}
Why notifyDbChanged() matters

After writing to the database, notifyDbChanged() fires an event that all hooks listen to. This is how useLinksBySpace() knows to re-fetch and show the new link on screen — without this, the UI would be out of sync with the database.

The LinkPreviewCard

Every saved link is displayed using the LinkPreviewCard component. It shows a thumbnail image (or brand logo, or fallback), the link title, and the domain name. Here's the actual code from the app:

Editing Links

When a user taps the edit action on a link, the app navigates to an edit screen or opens a sheet. The user can change the title, move the link to a different space, add or remove tags, and update the notes. Here's the repository function that handles updates:

src/repositories/links.ts — updateLink 
export function updateLink(
  db: DbClient,
  id: string,
  patch: UpdateLinkInput
): Link | null {
  const existing = selectLink(db, id);
  if (!existing) {
    return null;
  }

  const next: Link = {
    ...existing,
    title: patch.title !== undefined
      ? patch.title.trim() || existing.title
      : existing.title,
    spaceId: patch.spaceId !== undefined ? patch.spaceId : existing.spaceId,
    description:
      patch.description !== undefined ? patch.description : existing.description,
    thumbnail: patch.thumbnail !== undefined ? patch.thumbnail : existing.thumbnail,
    tags: patch.tags !== undefined ? patch.tags : existing.tags,
    updatedAt: Date.now(),
  };

  db.run(
    `UPDATE links
       SET title = ?, space_id = ?, description = ?, thumbnail = ?, tags = ?, updated_at = ?
     WHERE id = ?`,
    [next.title, next.spaceId, next.description, next.thumbnail,
     serializeTags(next.tags), next.updatedAt, id]
  );
  return next;
}

The pattern here is a patch — you only pass the fields you want to change. The function merges the patch with the existing link data, sets updatedAt to the current time, and writes it back to the database.

The hook that calls this is straightforward:

src/hooks/useLinks.ts — useUpdateLink 
export function useUpdateLink(): (id: string, patch: UpdateLinkInput) => Link | null {
  return (id, patch) => {
    const updated = updateLink(getDbClient(), id, patch);
    notifyDbChanged();
    return updated;
  };
}
Why patch.title.trim() || existing.title?

If the user clears the title, we fall back to the existing title. This prevents empty titles. The || operator means "use the left side if it's truthy, otherwise use the right side."

Deleting Links

Deleting a link removes it from the database permanently. Link Space shows a confirmation dialog before deleting — this prevents accidental data loss. Here's the repository function:

src/repositories/links.ts — deleteLink 
export function deleteLink(db: DbClient, id: string): void {
  db.run('DELETE FROM links WHERE id = ?', [id]);
}

And the hook that calls it:

src/hooks/useLinks.ts — useDeleteLink 
export function useDeleteLink(): (id: string) => void {
  return (id) => {
    deleteLink(getDbClient(), id);
    notifyDbChanged();
  };
}

In the UI, the delete action is triggered from a menu sheet or long-press. The app shows a confirmation dialog asking "Delete this link?" before actually calling the function. This is a best practice — destructive actions should always require confirmation.

No undo for deletes

Once a link is deleted, it's gone from the database. There's no "undo" button. That's why the confirmation dialog is important — it's the last chance to change your mind.

Pinning Links

Pinning a link marks it as important. Pinned links appear in a special panel at the top of the home screen, separate from the space they belong to. Here's the repository function:

src/repositories/links.ts — setPinned 
export function setPinned(db: DbClient, id: string, isPinned: boolean): void {
  db.run('UPDATE links SET is_pinned = ?, updated_at = ? WHERE id = ?', [
    isPinned ? 1 : 0,
    Date.now(),
    id,
  ]);
}

And the hook:

src/hooks/useLinks.ts — usePinLink 
export function usePinLink(): (id: string, isPinned: boolean) => void {
  return (id, isPinned) => {
    setPinned(getDbClient(), id, isPinned);
    notifyDbChanged();
  };
}

The pinned links are displayed using the DynamicIsland component on the home screen. The repository also has a function to list all pinned links:

src/repositories/links.ts — listPinned 
export function listPinned(db: DbClient): Link[] {
  const rows = db.all(
    `SELECT ${CURRENTLY_SELECTED_COLUMNS} FROM links
     WHERE is_pinned = 1 ORDER BY created_at DESC`
  );
  return rows.map((row) => mapLinkRow(row as never));
}
Why pinning matters

Pinning lets users surface their most important links without moving them out of their current space. A link can live in "Work Resources" but also be pinned to appear at the top of the home screen for quick access.

Moving Links Between Spaces

Users can move a link from one space to another. This simply updates the spaceId field in the database — the link itself doesn't change. Here's the repository function:

src/repositories/links.ts — moveLink 
export function moveLink(db: DbClient, id: string, spaceId: string | null): void {
  db.run('UPDATE links SET space_id = ?, updated_at = ? WHERE id = ?', [
    spaceId,
    Date.now(),
    id,
  ]);
}

And the hook:

src/hooks/useLinks.ts — useMoveLink 
export function useMoveLink(): (id: string, spaceId: string | null) => void {
  return (id, spaceId) => {
    moveLink(getDbClient(), id, spaceId);
    notifyDbChanged();
  };
}

Setting spaceId to null moves the link to "Recent Links" (the unorganized collection). This is how users can reorganize links without re-saving them.

Move vs. re-save

Moving a link is a lightweight operation — it just changes one field. Re-saving would create a duplicate. Always prefer moveLink() over creating a new link when reorganizing.

src/components/AddLinkForm.tsx 
import { useState } from 'react';
import { View, Text, TextInput, Pressable, StyleSheet } from 'react-native';
import { Ionicons } from '@expo/vector-icons';
import { useTheme } from '../theme/ThemeContext';
import { normalizeUrl, isValidUrl } from '../lib/url';
import { useSaveLink } from '../hooks/useLinks';
import { useSpaces } from '../hooks/useSpaces';

interface AddLinkFormProps {
  spaceId?: string | null;
  onSaved?: () => void;
}

export function AddLinkForm({ spaceId, onSaved }: AddLinkFormProps) {
  const { palette } = useTheme();
  const spaces = useSpaces();
  const saveLink = useSaveLink();

  const [url, setUrl] = useState('');
  const [title, setTitle] = useState('');
  const [selectedSpaceId, setSelectedSpaceId] = useState<string | null>(spaceId ?? null);
  const [error, setError] = useState('');
  const [saved, setSaved] = useState(false);

  function handleSave() {
    setError('');
    const trimmed = url.trim();

    if (!trimmed) {
      setError('Please enter a URL');
      return;
    }

    const normalized = normalizeUrl(trimmed);
    if (!normalized) {
      setError('Not a valid URL');
      return;
    }

    saveLink({
      url: normalized,
      title: title.trim() || undefined,
      spaceId: selectedSpaceId,
    });

    setSaved(true);
    setUrl('');
    setTitle('');

    setTimeout(() => {
      setSaved(false);
      onSaved?.();
    }, 1000);
  }

  return (
    <View style={[styles.container, { backgroundColor: palette.surface }]}>
      <Text style={[styles.label, { color: palette.textSecondary }]}>URL</Text>
      <TextInput
        value={url}
        onChangeText={(t) => { setUrl(t); setError(''); }}
        placeholder="https://example.com"
        placeholderTextColor={palette.textPlaceholder}
        style={[styles.input, { backgroundColor: palette.surfaceRaised, color: palette.textPrimary }]}
        autoCapitalize="none"
        autoCorrect={false}
        keyboardType="url"
      />

      {error ? (
        <Text style={styles.error}>{error}</Text>
      ) : null}

      <Text style={[styles.label, { color: palette.textSecondary }]}>Title (optional)</Text>
      <TextInput
        value={title}
        onChangeText={setTitle}
        placeholder="Page title"
        placeholderTextColor={palette.textPlaceholder}
        style={[styles.input, { backgroundColor: palette.surfaceRaised, color: palette.textPrimary }]}
      />

      <Text style={[styles.label, { color: palette.textSecondary }]}>Space</Text>
      <View style={styles.spaceRow}>
        {spaces.map((sp) => (
          <Pressable
            key={sp.id}
            onPress={() => setSelectedSpaceId(sp.id)}
            style={[
              styles.spaceChip,
              {
                backgroundColor: sp.id === selectedSpaceId
                  ? palette.accent
                  : palette.surfaceRaised,
              },
            ]}
          >
            <Text style={{ color: sp.id === selectedSpaceId ? '#fff' : palette.textPrimary, fontSize: 13 }}>
              {sp.name}
            </Text>
          </Pressable>
        ))}
      </View>

      <Pressable
        onPress={handleSave}
        disabled={saved}
        style={[
          styles.saveBtn,
          { backgroundColor: saved ? '#27C76F' : palette.accent },
        ]}
      >
        <Text style={styles.saveBtnText}>
          {saved ? 'Saved!' : 'Save Link'}
        </Text>
      </Pressable>
    </View>
  );
}
