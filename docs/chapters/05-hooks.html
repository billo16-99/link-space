Chapter 5

Hooks & State

Learn how React keeps your screens in sync with the database. useState, useEffect, custom hooks, and the data flow pattern that powers LinkSpice.

What You'll Learn

In this chapter, you'll understand:

  • React state — how components remember things
  • useState — the hook that stores data inside a component
  • useEffect — the hook that runs code when something changes
  • Custom hooks — reusable bundles of logic you write yourself
  • Data flow — how data moves from the database to your screen

What is State?

State is a variable inside a component that React watches. When state changes, React re-renders the screen — it redraws the UI with the new value.

Think of state like a whiteboard in a classroom. The teacher writes a number on it. Everyone sees the number. When the teacher erases it and writes a new number, everyone sees the new one. State works the same way — it holds a value, and when it changes, the screen updates.

useState example 
import { useState } from 'react';
import { Text, Button, View } from 'react-native';

export function Counter() {
  const [count, setCount] = useState(0);

  return (
    <View>
      <Text>You clicked {count} times</Text>
      <Button title="Add 1" onPress={() => setCount(count + 1)} />
    </View>
  );
}

Here is what happens step by step:

  1. useState(0) creates a variable called count with the starting value 0
  2. setCount is a function that changes the value of count
  3. When the user taps "Add 1", setCount(count + 1) runs
  4. React sees the state changed, so it redraws the screen with the new number
Why does setCount trigger a redraw?

React compares the old state with the new state. If they are different, it re-renders the component. This is how the screen stays in sync with your data.

What is useEffect?

useEffect runs code after the component renders. You use it to do things that are not part of rendering — like fetching data, subscribing to events, or setting up timers.

Think of it like a doorbell. You set it up once, and it rings whenever someone presses the button. You do not ring it yourself — it reacts to external events.

useEffect example 
import { useEffect, useState } from 'react';
import { Text, View } from 'react-native';

export function Timer() {
  const [seconds, setSeconds] = useState(0);

  useEffect(() => {
    const interval = setInterval(() => {
      setSeconds(prev => prev + 1);
    }, 1000);

    return () => clearInterval(interval);
  }, []);

  return (
    <View>
      <Text>Timer: {seconds}s</Text>
    </View>
  );
}

The useEffect call has two parts:

  1. The function — what to do. Here it starts a timer that adds 1 every second.
  2. The empty array [] — when to do it. An empty array means "run this only once, when the component first appears."
The cleanup function

The return () => clearInterval(interval) part is cleanup. It runs when the component disappears (like when the user leaves the screen). It stops the timer so it does not keep running in the background.

You can also watch specific values. If you put a variable in the array, the effect runs again whenever that variable changes:

useEffect with a dependency 
useEffect(() => {
  console.log('spaceId changed to:', spaceId);
  // fetch new data...
}, [spaceId]); // runs when spaceId changes

Custom Hooks

A custom hook is a function you write that uses other hooks inside it. It lets you bundle up logic so you can reuse it across many components.

Think of a custom hook like a recipe. You write it once, and anyone can follow it. Instead of rewriting the same code in every component, you put it in a custom hook and call it from anywhere.

Custom hook example 
import { useState } from 'react';

function useCounter(start: number) {
  const [count, setCount] = useState(start);

  function increment() {
    setCount(prev => prev + 1);
  }

  function reset() {
    setCount(start);
  }

  return { count, increment, reset };
}

// Now any component can use it:
export function MyScreen() {
  const { count, increment, reset } = useCounter(0);

  return (
    <View>
      <Text>Count: {count}</Text>
      <Button title="Add" onPress={increment} />
      <Button title="Reset" onPress={reset} />
    </View>
  );
}
Why custom hooks?

Without custom hooks, every component that needs to read from the database would repeat the same useState + useEffect code. With custom hooks, you write that logic once and every component gets it for free.

The useSpaces Hook

This is the real hook from the LinkSpice app. It reads all spaces from the database and keeps them updated automatically.

src/hooks/useSpaces.ts (simplified) 
import { useEffect, useState } from 'react';
import { getDbClient } from '../db/db';
import { listSpaces } from '../repositories/spaces';
import { subscribeToDbChanges } from '../store/events';
import type { Space } from '../types';

export function useSpaces(): Space[] {
  const [spaces, setSpaces] = useState<Space[]>(
    () => listSpaces(getDbClient())
  );

  useEffect(
    () =>
      subscribeToDbChanges(() =>
        setSpaces(listSpaces(getDbClient()))
      ),
    []
  );

  return spaces;
}

Line by line:

1
const [spaces, setSpaces] = useState<Space[]>(...) — Creates state that holds an array of spaces. The initial value comes from listSpaces(), which reads directly from the database. The () => form is called a lazy initializer — React only runs it once on the first render.
2
useEffect(() => subscribeToDbChanges(...), []) — Subscribes to the event system. Whenever something in the database changes (a space is added, edited, or deleted), the callback runs and re-reads all spaces from the database, updating state.
3
return spaces — Returns the current list of spaces. Any component that calls useSpaces() gets the array, and it updates automatically when the database changes.
Why the empty array []?

The empty array means "subscribe once when the component appears, and never re-subscribe." The subscription stays active forever — we just want to set it up a single time.

The useLinks Hook

This hook reads all links belonging to a specific space. It follows the exact same pattern as useSpaces.

src/hooks/useLinks.ts (simplified) 
import { useEffect, useState } from 'react';
import { getDbClient } from '../db/db';
import { listBySpace } from '../repositories/links';
import { subscribeToDbChanges } from '../store/events';
import type { Link } from '../types';

export function useLinksBySpace(spaceId: string | null): Link[] {
  const [links, setLinks] = useState<Link[]>(
    () => listBySpace(getDbClient(), spaceId)
  );

  useEffect(
    () =>
      subscribeToDbChanges(() =>
        setLinks(listBySpace(getDbClient(), spaceId))
      ),
    [spaceId]
  );

  return links;
}

The only difference from useSpaces: the dependency array has [spaceId] instead of []. This means if the user navigates to a different space, the effect re-subscribes with the new space ID.

Why does [spaceId] matter?

If you used [] here, the hook would always show links for the first space the user opened, even after they navigate to a different one. The dependency array tells React: "re-run this when spaceId changes."

The Event System

LinkSpice uses a tiny event system to notify hooks when the database changes. It lives in one file and has only two functions.

src/store/events.ts 
type Listener = () => void;

const listeners = new Set<Listener>();

export function subscribeToDbChanges(listener: Listener): () => void {
  listeners.add(listener);
  return () => {
    listeners.delete(listener);
  };
}

export function notifyDbChanged(): void {
  listeners.forEach((listener) => listener());
}

How it works:

1
listeners — A Set that holds all the functions waiting for database changes. Think of it like a mailing list.
2
subscribeToDbChanges(listener) — Adds a function to the list. Returns a cleanup function that removes it (so hooks can unsubscribe when they unmount).
3
notifyDbChanged() — Calls every listener in the list. This is what triggers hooks to re-read data from the database.
Where does notifyDbChanged get called?

Inside the action hooks like useAddSpace, useDeleteLink, etc. After writing to the database, they call notifyDbChanged() to tell all hooks "hey, data changed, re-read it."

Data Flow Pattern

Every piece of data in LinkSpice follows the same path. Understanding this pattern means you understand the entire app.

The data flow 
Database (SQLite)
    ↓
Repository (reads/writes SQL)
    ↓
Hook (useState + useEffect + subscribeToDbChanges)
    ↓
Component (displays the data as UI)
1
Database — The raw data lives here. Tables with rows and columns.
2
Repository — SQL queries that read or write to the database. Returns plain objects (like Space or Link).
3
Hook — Calls the repository to get data, stores it in state, and subscribes to changes so it stays fresh.
4
Component — Calls the hook, gets the data, and renders it as UI. When the hook updates, the component re-renders automatically.
Why not let components talk to the database directly?

Separation of concerns. The component does not need to know SQL. The repository does not need to know React. The hook is the glue. If you switch databases someday, you only change the repository — the components and hooks stay the same.

Building It

Let's put this into practice with two exercises: a simple counter, then a list that reads from the database.

Step 1: A Simple Counter

This teaches you how useState and useEffect work together.

Counter.tsx 
import { useState, useEffect } from 'react';
import { Text, Button, View, StyleSheet } from 'react-native';

export function Counter() {
  const [count, setCount] = useState(0);

  useEffect(() => {
    console.log('Count is now:', count);
  }, [count]);

  return (
    <View style={styles.container}>
      <Text style={styles.number}>{count}</Text>
      <Button title="Add 1" onPress={() => setCount(c => c + 1)} />
      <Button title="Reset" onPress={() => setCount(0)} />
    </View>
  );
}

const styles = StyleSheet.create({
  container: { flex: 1, justifyContent: 'center', alignItems: 'center' },
  number: { fontSize: 48, marginBottom: 16 },
});

When you run this, tapping "Add 1" changes the state, which triggers the useEffect (you'll see logs in the console), and React redraws the screen with the new number.

Step 2: A List from the Database

This is what the real app does — read data from the database using a hook.

SpaceList.tsx 
import { View, Text, StyleSheet } from 'react-native';
import { useSpaces } from '../src/hooks/useSpaces';

export function SpaceList() {
  const spaces = useSpaces();

  if (spaces.length === 0) {
    return <Text>No spaces yet. Create one!</Text>;
  }

  return (
    <View>
      {spaces.map(space => (
        <View key={space.id} style={styles.card}>
          <Text style={styles.name}>{space.name}</Text>
        </View>
      ))}
    </View>
  );
}

const styles = StyleSheet.create({
  card: {
    padding: 16,
    marginVertical: 4,
    backgroundColor: '#1a1a1e',
    borderRadius: 8,
  },
  name: { color: '#e4e4e7', fontSize: 16 },
});

Notice how clean the component is. It calls useSpaces(), gets an array, and maps over it. No SQL, no database imports, no event subscriptions — all of that is handled by the hook.

Verify it works

Before moving on, make sure you can confirm:

  • Screen shows data from the database (spaces or links appear on the screen)
  • Data updates when you add a new item (no restart needed — the screen refreshes automatically)
  • The console logs change when state updates
Try it yourself — create a useSettings hook

Follow the same pattern to create a hook that reads a single setting from the database:

src/hooks/useSettings.ts 
import { useEffect, useState } from 'react';
import { getDbClient } from '../db/db';
import { getSetting } from '../repositories/settings';
import { subscribeToDbChanges } from '../store/events';

export function useSettings(key: string): string | null {
  const [value, setValue] = useState<string | null>(
    () => getSetting(getDbClient(), key)
  );

  useEffect(
    () =>
      subscribeToDbChanges(() =>
        setValue(getSetting(getDbClient(), key))
      ),
    [key]
  );

  return value;
}
  1. Look at this hook — does it follow the same pattern as useSpaces?
  2. What would happen if you removed the [key] dependency from the array?
  3. Create a component that calls useSettings('theme') and displays the value
