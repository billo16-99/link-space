Chapter 3

Navigation

Learn how screens connect using expo-router's file-based routing and Stack navigation.

What You'll Learn

In this chapter you will learn the basics of screen navigation in LinkSpice. Specifically:

  • expo-router — the routing library LinkSpice uses to manage screens.
  • File-based routing — how dropping a file into the app/ folder automatically creates a screen.
  • Stack navigation — how screens pile on top of each other, just like a deck of cards.

By the end of this chapter you will have three screens — Home, About, and Profile — that you can move between on your phone.

How expo-router Works

expo-router turns every file inside the app/ directory into a screen. No extra configuration, no route definitions — the file system is the router.

Why file-based routing?

You do not need to write a list of routes somewhere. If you create app/about.tsx, you automatically get a screen at /about. This is simple and hard to get wrong.

Here is what a typical app/ folder looks like in LinkSpice:

app/ 
app/
├── _layout.tsx        ← the root navigator (wrap everything)
├── index.tsx          ← the home screen (/)
├── about.tsx          ← the about screen (/about)
├── profile/
│   └── [id].tsx       ← dynamic screen (/profile/42)
└── +not-found.tsx     ← 404 page

Every file here is a route. The underscore prefix in _layout.tsx tells expo-router "this is a layout, not a screen." The brackets in [id].tsx mean the segment is dynamic — it can be any value.

_layout.tsx Explanation

The root layout is the most important file in the entire app. It wraps every screen with the navigation stack, providers, and theme settings.

Here is the actual _layout.tsx from LinkSpice:

app/_layout.tsx 
import { Stack } from "expo-router";
import { AuthProvider } from "../lib/auth-provider";
import { useColorScheme } from "react-native";
import { Colors } from "../constants/Colors";

export default function RootLayout() {
  const colorScheme = useColorScheme();

  return (
    <AuthProvider>
      <Stack
        screenOptions={{
          headerStyle: {
            backgroundColor: Colors[colorScheme ?? "light"].background,
          },
          headerTintColor: Colors[colorScheme ?? "light"].text,
        }}
      >
        <Stack.Screen name="index" options={{ title: "LinkSpice" }} />
        <Stack.Screen name="about" options={{ title: "About" }} />
        <Stack.Screen name="profile/[id]" options={{ title: "Profile" }} />
      </Stack>
    </AuthProvider>
  );
}

Let us break this down piece by piece:

1

Stack from expo-router

This is the navigator. A Stack keeps screens in a pile — the newest one sits on top. When you go back, the top screen pops off and the one beneath becomes visible.

2

screenOptions

These are the default styles applied to every screen. Here we set the header background color and text color based on whether the phone is in light or dark mode.

3

<Stack.Screen> entries

Each entry configures one screen. The name must match the filename in app/. The title shows up in the header bar at the top of the screen.

4

<AuthProvider>

This wraps the entire navigation tree so that every screen can access the current user. You built this provider in Chapter 2.

Tip

You will modify _layout.tsx every time you add a new screen. Always add a matching Stack.Screen entry so the header title is set correctly.

Navigating Between Screens

LinkSpice uses the router object from expo-router to move between screens. There are three main methods you need to know:

1

router.push(href)

Adds a new screen on top of the current one. The user can press Back to return. Think of it as placing another card on the deck.

Example 
router.push("/about");
2

router.back()

Goes to the previous screen in the stack. Same as pressing the back arrow in the header.

Example 
router.back();
3

router.replace(href)

Swaps the current screen instead of stacking. The user cannot go back to the replaced screen. Use this for login flows or redirects.

Example 
router.replace("/");
Why three methods?

push builds history. back steps through it. replace replaces the last entry. You will use push most of the time, back for back buttons, and replace when you do not want the user to return.

Building the Navigation

Time to create three screens and wire them together. Follow each step carefully.

1

Create the Home screen

Open app/index.tsx and replace its contents with this:

app/index.tsx 
import { View, Text, Button, StyleSheet } from "react-native";
import { router } from "expo-router";

export default function HomeScreen() {
  return (
    <View style={styles.container}>
      <Text style={styles.title}>Welcome to LinkSpice</Text>
      <Text style={styles.subtitle}>Your links. Your space.</Text>
      <View style={styles.buttons}>
        <Button
          title="Go to About"
          onPress={() => router.push("/about")}
        />
        <Button
          title="Go to Profile"
          onPress={() => router.push("/profile/1")}
        />
      </View>
    </View>
  );
}

const styles = StyleSheet.create({
  container: {
    flex: 1,
    justifyContent: "center",
    alignItems: "center",
    padding: 20,
  },
  title: { fontSize: 28, fontWeight: "bold", marginBottom: 8 },
  subtitle: { fontSize: 16, color: "#888", marginBottom: 24 },
  buttons: { gap: 12 },
});

This is your home screen. It shows a greeting and two buttons — one that pushes to About and one that pushes to Profile.

2

Create the About screen

Create a new file at app/about.tsx:

app/about.tsx 
import { View, Text, Button, StyleSheet } from "react-native";
import { router } from "expo-router";

export default function AboutScreen() {
  return (
    <View style={styles.container}>
      <Text style={styles.title}>About LinkSpice</Text>
      <Text style={styles.body}>
        LinkSpice helps you collect and share your favorite links in one
        beautiful space.
      </Text>
      <Button title="Go Back" onPress={() => router.back()} />
    </View>
  );
}

const styles = StyleSheet.create({
  container: {
    flex: 1,
    justifyContent: "center",
    alignItems: "center",
    padding: 20,
  },
  title: { fontSize: 24, fontWeight: "bold", marginBottom: 12 },
  body: { fontSize: 16, color: "#555", textAlign: "center", marginBottom: 24 },
});

This screen has a back button that calls router.back().

3

Create the Profile screen

Create a new file at app/profile/[id].tsx. The [id] part is a dynamic segment — we will cover it in detail in the next section.

app/profile/[id].tsx 
import { View, Text, Button, StyleSheet } from "react-native";
import { router, useLocalSearchParams } from "expo-router";

export default function ProfileScreen() {
  const { id } = useLocalSearchParams<{ id: string }>();

  return (
    <View style={styles.container}>
      <Text style={styles.title}>Profile</Text>
      <Text style={styles.body}>Viewing profile for user #{id}</Text>
      <Button title="Go Back" onPress={() => router.back()} />
    </View>
  );
}

const styles = StyleSheet.create({
  container: {
    flex: 1,
    justifyContent: "center",
    alignItems: "center",
    padding: 20,
  },
  title: { fontSize: 24, fontWeight: "bold", marginBottom: 12 },
  body: { fontSize: 16, color: "#555", marginBottom: 24 },
});

This screen reads the id from the URL and displays it. You can pass any number in the link and it will work.

4

Update _layout.tsx

Make sure your root layout has all three screens listed. Use the code from the _layout.tsx Explanation section above.

5

Run the app

Start the development server and test on your phone or emulator:

Terminal 
npx expo start

URL Parameters

The Profile screen uses a dynamic route. The file [id].tsx tells expo-router that the /profile/ segment can contain any value.

URL structure 
/profile/1    ← id = "1"
/profile/42   ← id = "42"
/profile/abc  ← id = "abc"

To read the value inside the screen, use the useLocalSearchParams hook from expo-router:

Reading URL params 
const { id } = useLocalSearchParams<{ id: string }>();

You can pass parameters from anywhere by including them in the URL:

Pushing with a parameter 
router.push("/profile/42");
Warning

The id value is always a string. If you need a number, convert it yourself with Number(id) or parseInt(id, 10). expo-router never converts types for you.

Tip

You can add multiple dynamic segments by creating files like app/user/[userId]/post/[postId].tsx. Each bracketed segment becomes a parameter you can read.

Verify

Open the app on your phone and confirm these behaviours:

  • Home screen shows "Welcome to LinkSpice" with two buttons.
  • Tapping "Go to About" slides to the About screen. The back arrow in the header returns you to Home.
  • Tapping "Go to Profile" slides to the Profile screen showing "Viewing profile for user #1".
  • Pressing the back button on Profile returns to Home.
  • If you change the number in router.push("/profile/99"), the Profile screen updates accordingly.
Exercise

Challenge yourself — add a fourth screen called Settings.

  1. Create a new file at app/settings.tsx.
  2. Add a <Stack.Screen name="settings" options={{ title: "Settings" }} /> entry in _layout.tsx.

  4. Put something unique on the Settings screen — maybe a toggle or a list of options.

When you are done, you should be able to navigate to all four screens without errors.
