Chapter 2

Project Structure

Understand every folder and file in the LinkSpice app. Know what goes where and why.

What You'll Learn

In this chapter, you'll understand:

  • What a project structure is — the layout of folders and files in your app
  • Why files are organized in folders — keeping things tidy so you can find them
  • What each folder does — the job of every directory in LinkSpice

The Big Picture

Think of a project structure like the floor plan of a house. Every room has a purpose: the kitchen is for cooking, the bedroom is for sleeping. Code works the same way — each folder has a job.

Here is the full folder tree of the LinkSpice app:

Why does this matter?

When your app has 50+ files, you need to know where to look. This structure means you will always find things quickly — screens in app/, logic in src/.

The app/ Folder (Screens)

The app/ folder is where every screen lives. Each file in here becomes a screen in the app — that is called file-based routing.

It works like this:

  • app/index.tsx becomes the Home screen
  • app/search.tsx becomes the Search screen
  • app/settings.tsx becomes the Settings screen

See the pattern? The filename becomes the screen name.

About _layout.tsx

This file starts with an underscore because it is special. It does not become a screen — instead, it wraps all other screens and provides the navigation structure (like a tab bar at the bottom).

Some folders inside app/ have a [id].tsx file. The square brackets mean the ID is dynamic — it changes based on what the user is viewing. For example, app/space/[id].tsx handles every space, not just one.

The src/ Folder (Logic)

The src/ folder holds all the "brain" of the app — the data, components, database, and helper functions. It is everything the app needs to actually work, separate from what the user sees.

Here is the breakdown:

  • components/ — Reusable UI pieces (buttons, cards, inputs)
  • db/ — Database definitions and connection
  • repositories/ — Data operations (save, load, delete)
  • hooks/ — Connectors between database and screens
  • lib/ — Utility helpers (format dates, generate IDs, etc.)
  • store/ — Event system for app-wide communication
  • theme/ — Colors, spacing, typography definitions

src/components/ (UI Building Blocks)

A component is a reusable piece of the user interface. Think of it like LEGO bricks — you build small pieces, then snap them together to make something bigger.

For example, a Button component can be reused on every screen instead of rewriting the button code each time.

src/components/Button.tsx 
import { TouchableOpacity, Text, StyleSheet } from 'react-native';

interface ButtonProps {
  title: string;
  onPress: () => void;
}

export function Button({ title, onPress }: ButtonProps) {
  return (
    <TouchableOpacity style={styles.button} onPress={onPress}>
      <Text style={styles.text}>{title}</Text>
    </TouchableOpacity>
  );
}

const styles = StyleSheet.create({
  button: {
    backgroundColor: '#a56bff',
    paddingVertical: 12,
    paddingHorizontal: 24,
    borderRadius: 12,
    alignItems: 'center',
  },
  text: {
    color: '#fff',
    fontSize: 16,
    fontWeight: '600',
  },
});

This component takes a title and an onPress function, and renders a styled button. Any screen can use it by importing Button and passing props.

src/db/ (Database)

A database is like a spreadsheet that lives on the phone. It stores all the user's data — links, spaces, and settings — so it is still there when the app closes and reopens.

Why not just store data in variables?

Variables disappear when the app closes. A database saves data to the phone's storage permanently. LinkSpice uses SQLite, a lightweight database that runs right on the device.

The key file is schema.ts, which defines the "tables" — think of tables as different sheets in a spreadsheet:

src/db/schema.ts 
export const CREATE_SPACES_TABLE = `
  CREATE TABLE IF NOT EXISTS spaces (
    id TEXT PRIMARY KEY,
    name TEXT NOT NULL,
    icon TEXT,
    color TEXT,
    created_at TEXT DEFAULT CURRENT_TIMESTAMP
  )
`;

export const CREATE_LINKS_TABLE = `
  CREATE TABLE IF NOT EXISTS links (
    id TEXT PRIMARY KEY,
    url TEXT NOT NULL,
    title TEXT,
    description TEXT,
    space_id TEXT,
    is_pinned INTEGER DEFAULT 0,
    created_at TEXT DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (space_id) REFERENCES spaces(id)
  )
`;

This says: "Create a spaces table with columns for id, name, icon, color, and creation date. Create a links table with columns for id, URL, title, description, and which space it belongs to."

src/repositories/ (Data Operations)

Repositories handle CRUD — the four things you can do with data:

  1. Create — Add a new link or space
  2. Read — Load links and spaces from the database
  3. Update — Edit an existing link or space
  4. Delete — Remove a link or space
src/repositories/links.ts (simplified) 
export async function getLinks(spaceId: string) {
  const rows = await db.getAllAsync(
    'SELECT * FROM links WHERE space_id = ? ORDER BY created_at DESC',
    [spaceId]
  );
  return rows.map(mapRowToLink);
}

export async function createLink(link: NewLink) {
  await db.runAsync(
    'INSERT INTO links (id, url, title, space_id) VALUES (?, ?, ?, ?)',
    [link.id, link.url, link.title, link.spaceId]
  );
}

export async function deleteLink(id: string) {
  await db.runAsync('DELETE FROM links WHERE id = ?', [id]);
}

src/hooks/ (Connectors)

Hooks connect the database to the screen. They sit in the middle: they fetch data from the database and hand it to the screen so it can display it.

Think of hooks as waiters

The screen orders data ("bring me all links"), the hook goes to the database, gets the data, and brings it back. The screen does not talk to the database directly.

When data changes in the database, the hook automatically updates the screen. This is why when you add a link, it appears instantly without restarting the app.

src/theme/ (Colors & Style)

The theme/ folder is the design system — the single source of truth for every color, font size, and spacing value in the app.

src/theme/tokens.ts 
export const tokens = {
  colors: {
    accent: '#a56bff',
    background: '#0a0a0c',
    card: '#1a1a1e',
    text: '#e4e4e7',
    textSecondary: '#92959f',
    border: '#2a2a30',
    green: '#27c76f',
    red: '#ff5c68',
  },
  spacing: {
    xs: 4,
    sm: 8,
    md: 16,
    lg: 24,
    xl: 32,
  },
  fontSize: {
    sm: 13,
    md: 15,
    lg: 18,
    xl: 24,
  },
};

Instead of writing "#a56bff" everywhere, components use tokens.colors.accent. If you ever want to change the accent color, you change it in one place and it updates everywhere.

Key Files

At the root of the project, there are a few important config files:

package.json 
{
  "name": "link-space",
  "version": "1.0.0",
  "dependencies": {
    "expo": "~57.0.24",
    "expo-router": "~57.0.22",
    "expo-sqlite": "~57.0.3",
    "react": "19.2.3",
    "react-native": "0.86.3"
  }
}

This file lists every library the project depends on. The key ones are:

  • expo — The framework for building the app
  • expo-router — File-based navigation (the app/ folder system)
  • expo-sqlite — The SQLite database on the phone
  • react and react-native — The UI library and mobile runtime
