Chapter 8

Theme & Polish

Add dark/light mode, responsive layouts, and smooth animations to make your app feel professional. This is where Link Space goes from "working" to "delightful."

What You'll Learn

In this chapter, you'll understand:

  • Design tokens — a single source of truth for colors, spacing, and typography
  • Dark/light mode — how ThemeProvider wraps the app and lets users switch themes
  • Responsive design — adapting layouts for different screen sizes with useResponsive
  • Animations — spring physics and the Animated API for smooth motion

Why tokens matter

Without tokens, you'd scatter hex values like #1A1A1E throughout your components. If you later want to change the surface color, you'd have to find and replace it in dozens of files. With tokens, you change one value in tokens.ts and every component updates automatically.

ThemeContext — How the Theme Is Delivered

React's Context API lets you pass data down through the component tree without prop-drilling. Link Space uses it to deliver the current theme (palette, mode, and a function to switch modes) to every component in the app.

src/theme/ThemeContext.tsx 
import { createContext, useCallback, useContext, useMemo, useState } from 'react';
import type { ReactNode } from 'react';
import { useColorScheme } from 'react-native';
import Storage from 'expo-sqlite/kv-store';

import type { AppearanceMode } from '../types';
import { palettes, resolveAppearance, type Palette } from './tokens';

const MODE_KEY = 'appearance_mode';

export interface ThemeContextValue {
  mode: AppearanceMode;
  setMode: (mode: AppearanceMode) => void;
  resolvedMode: 'dark' | 'light';
  palette: Palette;
}

const ThemeContext = createContext<ThemeContextValue | null>(null);

function readStoredMode(): AppearanceMode {
  try {
    const raw = Storage.getItemSync(MODE_KEY);
    if (raw === 'dark' || raw === 'light' || raw === 'system') {
      return raw;
    }
  } catch {
    // Storage not ready yet; fall back to dark.
  }
  return 'dark';
}

export function ThemeProvider({ children }: { children: ReactNode }) {
  const rawScheme = useColorScheme();
  const systemScheme: 'dark' | 'light' = rawScheme === 'dark' ? 'dark' : 'light';
  const [mode, setModeState] = useState<AppearanceMode>(readStoredMode);

  const setMode = useCallback((next: AppearanceMode) => {
    setModeState(next);
    try {
      Storage.setItemSync(MODE_KEY, next);
    } catch {
      // Persisting the preference is best-effort.
    }
  }, []);

  const value = useMemo<ThemeContextValue>(() => {
    const resolvedMode = resolveAppearance(mode, systemScheme);
    return {
      mode,
      setMode,
      resolvedMode,
      palette: palettes[resolvedMode],
    };
  }, [mode, systemScheme, setMode]);

  return (
    <ThemeContext.Provider value={value}>
      {children}
    </ThemeContext.Provider>
  );
}

export function useTheme(): ThemeContextValue {
  const ctx = useContext(ThemeContext);
  if (!ctx) {
    throw new Error('useTheme must be used within a ThemeProvider');
  }
  return ctx;
}

Here's the flow, step by step:

1
readStoredMode() — On app start, reads the user's saved preference from SQLite's key-value store. If nothing is saved, it defaults to 'dark'.
2
useColorScheme() — A React Native hook that tells you whether the phone itself is in dark or light mode. This is the "system" setting.
3
resolveAppearance(mode, systemScheme) — If the user picked 'system', it uses the phone's setting. Otherwise it uses the user's explicit choice. Returns either 'dark' or 'light'.
4
palette: palettes[resolvedMode] — Looks up the right palette from the tokens file. If resolved mode is 'dark', you get the dark colors. If 'light', you get the light colors.
How components use it

Any component can call const { palette } = useTheme() and get the current colors. No prop drilling, no imports of palettes — just one hook call and the right colors appear.

Dark/Light Mode Switching

The setMode function from useTheme() accepts three values: 'dark', 'light', or 'system'. When a user taps a toggle, you call setMode('light') and every component in the app re-renders with the new palette.

Using setMode in a component 
import { Pressable, Text, View } from 'react-native';
import { useTheme } from '../theme/ThemeContext';

export function ThemeToggle() {
  const { mode, setMode, resolvedMode } = useTheme();

  return (
    <View>
      <Text>Current mode: {resolvedMode}</Text>

      <Pressable onPress={() => setMode('dark')}>
        <Text>Dark</Text>
      </Pressable>

      <Pressable onPress={() => setMode('light')}>
        <Text>Light</Text>
      </Pressable>

      <Pressable onPress={() => setMode('system')}>
        <Text>System</Text>
      </Pressable>
    </View>
  );
}

The preference is persisted using Storage.setItemSync(MODE_KEY, next) — so the user's choice survives app restarts. On the next launch, readStoredMode() picks it back up.

Why 'system' is an option

Most users expect their phone's global dark/light setting to carry through to apps. The 'system' mode does exactly that — it follows whatever the phone is set to. This is the default in Link Space if no preference has been saved.

Responsive Design — useResponsive

Phones come in many sizes. Link Space uses a custom hook called useResponsive that reads the screen dimensions and returns a set of pre-calculated values that adjust automatically for small, normal, and large phones.

src/hooks/useResponsive.ts 
import { useWindowDimensions } from 'react-native';

export function useResponsive() {
  const { width, height } = useWindowDimensions();

  const isSmall = width < 360;
  const isNormal = width >= 360 && width < 412;
  const isLarge = width >= 412;

  const columns: 1 | 2 = isSmall ? 1 : 2;

  const iconSize = isSmall ? 18 : isNormal ? 20 : 22;
  const headerIconSize = isSmall ? 20 : isNormal ? 24 : 28;

  const tileSize = isSmall ? 36 : isNormal ? 42 : 48;

  const pagePad = isSmall ? 16 : isNormal ? 20 : 24;

  const columnGap = isSmall ? 10 : isNormal ? 14 : 16;
  const rowGap = isSmall ? 12 : isNormal ? 16 : 18;

  const searchHeight = isSmall ? 46 : isNormal ? 50 : 54;
  const searchIconSize = isSmall ? 16 : isNormal ? 17 : 18;
  const filterSize = isSmall ? 30 : isNormal ? 34 : 36;

  const cardPadding = isSmall ? 16 : isNormal ? 18 : 22;
  const cardRadius = isSmall ? 20 : isNormal ? 24 : 28;

  const pillHeight = isSmall ? 32 : isNormal ? 36 : 40;
  const pillDotSize = isSmall ? 8 : isNormal ? 9 : 10;

  const fabWidth = isSmall ? 170 : isNormal ? 190 : 210;
  const fabHeight = isSmall ? 50 : isNormal ? 54 : 58;
  const fabIconCircle = isSmall ? 34 : isNormal ? 38 : 40;
  const fabPlusSize = isSmall ? 20 : isNormal ? 22 : 24;
  const fabTextSize = isSmall ? 15 : isNormal ? 16 : 17;

  const sectionTitleSize = isSmall ? 22 : isNormal ? 25 : 27;
  const cardTitleSize = isSmall ? 16 : isNormal ? 17 : 19;
  const linkCountSize = isSmall ? 13 : isNormal ? 14 : 16;
  const categorySize = isSmall ? 12 : isNormal ? 13 : 15;

  return {
    width, height, columns, iconSize, headerIconSize,
    tileSize, pagePad, columnGap, rowGap, searchHeight,
    searchIconSize, filterSize, cardPadding, cardRadius,
    pillHeight, pillDotSize, fabWidth, fabHeight, fabIconCircle,
    fabPlusSize, fabTextSize, sectionTitleSize, cardTitleSize,
    linkCountSize, categorySize,
  };
}

The hook divides phones into three buckets:

1
Small (< 360px) — Compact sizes for narrow phones. Uses 1-column layout for space cards.
2
Normal (360–411px) — The baseline. Most mid-range phones land here. Uses 2-column layout.
3
Large (≥ 412px) — Larger phones and tablets get more padding and bigger icons.
How components use it

Components call const r = useResponsive() and then use r.pagePad, r.cardRadius, etc. in their styles. The layout adapts automatically when the screen resizes — no manual breakpoint logic needed.

Animations — The Animated API

React Native's Animated API lets you create smooth animations without worrying about frame timing. You define a start value, an end value, and a "spring" or "timing" curve, and the library handles the in-between frames for you.

Animation basics 
import { useRef } from 'react';
import { Animated, Easing } from 'react-native';

// Create an animated value (starts at 0)
const scaleAnim = useRef(new Animated.Value(1)).current;

// Spring animation — natural, bouncy feel
Animated.spring(scaleAnim, {
  toValue: 0.95,        // shrink to 95%
  useNativeDriver: true, // runs on UI thread for smoothness
  damping: 18,           // how much bounce (lower = more bounce)
  stiffness: 180,        // how fast it springs (higher = faster)
}).start();

// Timing animation — precise duration
Animated.timing(scaleAnim, {
  toValue: 1,
  duration: 250,
  easing: Easing.out(Easing.cubic), // ease-out curve
  useNativeDriver: true,
}).start();

Springs feel natural because they mimic real physics. Timing animations give you exact control over duration. Link Space uses both — springs for interactive motions (press feedback, panel slides) and timing for predictable transitions (fade in/out).

Why useNativeDriver: true?

This tells React Native to run the animation on the native UI thread instead of the JavaScript thread. The result: buttery-smooth 60fps animations even when JavaScript is busy doing other work. Always use this unless you're animating a property that the native driver doesn't support (like backgroundColor).

Real Animation: AddLinkPanel

The AddLinkPanel is the bottom sheet that slides up when you tap "Add Link." It uses several animated values working together to create a polished feel. Here's how the key animations are set up:

src/components/AddLinkPanel.tsx (animation setup) 
const slideAnim = useRef(new Animated.Value(0)).current;
const fadeAnim = useRef(new Animated.Value(0)).current;
const swipeY = useRef(new Animated.Value(0)).current;
const saveScale = useRef(new Animated.Value(1)).current;
const saveCheckmark = useRef(new Animated.Value(0)).current;

Each value controls a different piece of the animation:

1
slideAnim — The panel's Y position. Starts off-screen (at PANEL_H) and springs to 0 (fully visible) when opened.
2
fadeAnim — The backdrop opacity. Fades from 0 to 1 when the panel opens, and back to 0 when it closes.
3
swipeY — Tracks the user's drag gesture. When they swipe down, this value follows their finger. If they swipe far enough, the panel closes.
4
saveScale — The save button's scale. Shrinks to 0.92 and bounces back to 1 when the link is saved.
5
saveCheckmark — The checkmark icon opacity. Fades in from 0 to 1 after saving.

Opening and Closing

AddLinkPanel.tsx (open/close animation) 
useEffect(() => {
  if (expanded) {
    slideAnim.setValue(PANEL_H);
    fadeAnim.setValue(0);
    swipeY.setValue(0);
    Animated.parallel([
      Animated.spring(slideAnim, {
        toValue: 0,
        useNativeDriver: true,
        damping: 18,
        stiffness: 180,
      }),
      Animated.timing(fadeAnim, {
        toValue: 1,
        duration: 250,
        easing: Easing.out(Easing.cubic),
        useNativeDriver: true,
      }),
    ]).start();
  } else {
    Animated.parallel([
      Animated.timing(slideAnim, {
        toValue: PANEL_H,
        duration: 280,
        easing: Easing.out(Easing.cubic),
        useNativeDriver: true,
      }),
      Animated.timing(fadeAnim, {
        toValue: 0,
        duration: 180,
        easing: Easing.in(Easing.cubic),
        useNativeDriver: true,
      }),
    ]).start();
  }
}, [expanded]);

Notice the pattern: Animated.parallel() runs multiple animations at the same time. The spring and timing finish together, creating a cohesive slide-up effect.

Save Button Bounce

AddLinkPanel.tsx (save animation) 
useEffect(() => {
  if (saved) {
    Animated.sequence([
      Animated.spring(saveScale, {
        toValue: 0.92,
        useNativeDriver: true,
        damping: 12,
        stiffness: 300,
      }),
      Animated.spring(saveScale, {
        toValue: 1,
        useNativeDriver: true,
        damping: 14,
        stiffness: 200,
      }),
    ]).start();
    Animated.timing(saveCheckmark, {
      toValue: 1,
      duration: 200,
      easing: Easing.out(Easing.cubic),
      useNativeDriver: true,
    }).start();
  }
}, [saved]);

Animated.sequence() runs animations one after another. First the button shrinks, then it bounces back. Meanwhile, the checkmark fades in. This creates the satisfying "saved!" feedback.

Micro-Animations — The Small Touches

The best apps have tiny animations that you barely notice but would miss if they were gone. Link Space has several of these:

1

Card press scale

Every card in the app shrinks slightly when pressed. This gives tactile feedback — the user feels like they're pushing a physical button.

Pressable style function 
<Pressable
  onPress={onPress}
  style={({ pressed }) => [
    styles.card,
    { transform: [{ scale: pressed ? 0.98 : 1 }] },
  ]}
>
2

Panel slide-up

The AddLinkPanel doesn't just pop in. It slides up from the bottom with a spring curve while the backdrop fades in. This makes the transition feel physical, not digital.

3

Save button feedback

When you save a link, the button shrinks and bounces back while a checkmark fades in. This tells the user "it worked" without showing a toast or alert.

4

Swipe to dismiss

The AddLinkPanel can be swiped down to close. It tracks the finger in real-time, and if the user swipes far enough, it dismisses. Otherwise it springs back. This feels like handling a physical sheet of paper.

The rule of micro-animations

Keep them under 300ms. Use spring physics (damping 12–20, stiffness 150–300). Always use useNativeDriver: true. The animation should feel like a natural extension of the interaction, not a showpiece.

Building It

Let's put it all together. You'll add a theme toggle button and make a component animate on press.

1

Create a theme toggle

Add a simple component that lets the user switch between dark and light mode.

src/components/ThemeToggle.tsx 
import { Pressable, StyleSheet, Text, View } from 'react-native';
import { Ionicons } from '@expo/vector-icons';
import { useTheme } from '../theme/ThemeContext';

export function ThemeToggle() {
  const { resolvedMode, setMode } = useTheme();

  return (
    <View style={styles.row}>
      <Pressable
        onPress={() => setMode('dark')}
        style={({ pressed }) => [
          styles.btn,
          { opacity: pressed ? 0.7 : 1 },
          resolvedMode === 'dark' && styles.active,
        ]}
      >
        <Ionicons name="moon" size={16} color={resolvedMode === 'dark' ? '#FFFFFF' : '#92959F'} />
      </Pressable>

      <Pressable
        onPress={() => setMode('light')}
        style={({ pressed }) => [
          styles.btn,
          { opacity: pressed ? 0.7 : 1 },
          resolvedMode === 'light' && styles.active,
        ]}
      >
        <Ionicons name="sunny" size={16} color={resolvedMode === 'light' ? '#000000' : '#92959F'} />
      </Pressable>

      <Pressable
        onPress={() => setMode('system')}
        style={({ pressed }) => [
          styles.btn,
          { opacity: pressed ? 0.7 : 1 },
        ]}
      >
        <Ionicons name="phone-portrait" size={16} color="#92959F" />
      </Pressable>
    </View>
  );
}

const styles = StyleSheet.create({
  row: { flexDirection: 'row', gap: 8 },
  btn: {
    width: 36, height: 36, borderRadius: 18,
    alignItems: 'center', justifyContent: 'center',
    backgroundColor: '#1A1A1E',

2

Create an animated card

Build a component that uses spring animations when pressed.

src/components/AnimatedCard.tsx 
import { useRef } from 'react';
import { Animated, Pressable, StyleSheet, Text, View } from 'react-native';
import { useTheme } from '../theme/ThemeContext';

interface AnimatedCardProps {
  title: string;
  onPress?: () => void;
}

export function AnimatedCard({ title, onPress }: AnimatedCardProps) {
  const { palette } = useTheme();
  const scale = useRef(new Animated.Value(1)).current;

  function onPressIn() {
    Animated.spring(scale, {
      toValue: 0.95,
      useNativeDriver: true,
      damping: 15,
      stiffness: 400,
    }).start();
  }

  function onPressOut() {
    Animated.spring(scale, {
      toValue: 1,
      useNativeDriver: true,
      damping: 15,
      stiffness: 400,
    }).start();
  }

  return (
    <Animated.View style={{ transform: [{ scale }] }}>
      <Pressable
        onPress={onPress}
        onPressIn={onPressIn}
        onPressOut={onPressOut}
        style={[styles.card, { backgroundColor: palette.surface }]}
      >
        <Text style={{ color: palette.textPrimary, fontSize: 16 }}>
          {title}
        </Text>
      </Pressable>
    </Animated.View>
  );
}

const styles = StyleSheet.create({
  card: { padding: 20, borderRadius: 16 },
});
